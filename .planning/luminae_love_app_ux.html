01

The problem this solves

Business context
$600B+ Lost annually in global supply chains due to fraud, counterfeiting, and opacity. Companies cannot verify whether a product's journey from factory to shelf is authentic or tampered with — and today's analytics tools don't talk to blockchain records. They live in disconnected silos.
What ChainLens does
ChainLens records every product movement event immutably on-chain using Ethereum smart contracts. A Python indexer then pulls those events into a database and surfaces them through a real-time analytics dashboard. The result: a single pane of glass where a business can verify product provenance AND track supply chain KPIs simultaneously — something no off-the-shelf tool currently does cleanly.
★
Why this is the right portfolio project: It is not a tutorial clone. It solves a real, documented industry pain point. It combines two high-demand skill sets into one coherent product. And it produces live demos, deployed smart contracts, and data visualizations — all tangible, clickable proof-of-work that a hiring manager can actually open.

AI tools — how to use them

The rule: use AI to learn, not to skip learning
Using AI is a real, expected skill in 2025. You should use it. But every AI-generated snippet you paste must be something you can explain line by line in an interview. If you cannot explain it, do not ship it. Document your AI usage openly in your README — recruiters who use AI themselves will respect it.

Core features to build

Blockchain layer — smart contracts
  • ProductRegistry.sol — registers a product with a unique ID, manufacturer wallet address, and block timestamp. The entry is permanent and anyone can query it.
  • ShipmentTracker.sol — emits on-chain events for each checkpoint (factory → warehouse → distributor → retailer). Every event is immutable and timestamped by block.
  • Custody transfer — transferring ownership between wallet addresses with on-chain signatures. Simulates a real company-to-company handoff.
  • QR verification page — generate a QR code per product that deep-links to a public page showing the product's complete, verified blockchain history.
Analytics layer — data & insights
  • Event indexer service — a Web3.py Python script that continuously polls Sepolia for contract events and writes them to your database for fast analytics queries.
  • KPI dashboard — average transit time per supply chain leg, on-time delivery rate, checkpoint bottleneck detection, and shipment volume trends over time.
  • Anomaly detection — flag shipments that sat too long at a checkpoint or had unexpected custody changes. A Z-score model on dwell times is sufficient and impressive.
  • Exportable reports — CSV and PDF export for any date range. This tiny feature signals that you understand real business workflows, not just code.

Build milestones

Week
1
Project scaffolding + ProductRegistry contract
Initialize your GitHub repo on day 1 (public, from day 1 — your commit history matters). Set up Hardhat. Write and locally test ProductRegistry.sol. Deploy to Sepolia testnet. Paste the contract address in your README. Use Claude to explain any Solidity error messages — but write the final code yourself and understand every line.
Week
2
ShipmentTracker contract + test coverage
Add the tracking contract with checkpoint events and custody transfer. Write Hardhat unit tests targeting 90%+ branch coverage. Design your event schema carefully — what fields each event emits drives your entire analytics layer downstream. Spend real time on this design decision.
Wks
3–4
Python indexer + database + realistic seed data
Build the Web3.py event-polling service and write events to SQLite. Generate realistic mock shipment data using Python's Faker library — you need hundreds of records so your dashboard actually looks useful. Write the Pandas transformations for each KPI. Build the FastAPI endpoints that serve the dashboard.
Week
5
React dashboard + wallet connection + charts
Build the frontend. Connect RainbowKit so users can sign in with MetaMask. Display the KPI charts. Build the product lookup page — anyone can paste a product ID and see its complete, verified chain history with timestamps and wallet addresses. This single feature is your showstopper demo moment.
Week
6
Anomaly detection + reports + QR codes
Add Z-score anomaly flagging on checkpoint dwell times. Flag anomalies visually in the dashboard. Build CSV and PDF export. Generate QR codes using Python's qrcode library. Deploy to Vercel (frontend) and Railway (backend) by end of this week — do not wait until you're "done."
Wks
7–8
Polish, document, and promote
Write a stellar README: architecture diagram, demo GIF or screenshot, live URLs, setup guide, and a dedicated "How I used AI" section. Record a 3-minute Loom walkthrough. Write a LinkedIn post explaining the problem you solved and what you learned. Add the live URL and contract address to your resume. This is the week most students skip — don't.
✦
Stretch goals — only pursue these if the core is fully deployed and polished: multi-chain support (add Polygon Amoy) · Chainlink oracle for live logistics price feeds · The Graph protocol subgraph for decentralized data indexing · Role-based access control in the contract (manufacturer vs. distributor roles) · Mobile-responsive PWA

Mistakes that will kill your portfolio

✕
Tutorial clones. Building a CryptoZombies or DeFi Bootcamp clone tells a recruiter you can follow instructions. ChainLens is original — it solves a real problem. Protect that differentiation at all costs.
✕
No live deployment. "I built it locally" reads as unfinished. A zip file is not a portfolio piece. Deploy by the end of week 6 no matter how imperfect it is — you can iterate after.
✕
Private repos. If your GitHub shows one giant commit pushed the night before you applied, it signals you built nothing or copied everything. Public from day 1 — let the commit history speak for you.
✕
Scope creep. No NFTs, no DAO governance, no DeFi yield farming in v1. Ship the core described here, then and only then add a stretch feature. Students who try to build everything finish nothing.
✕
Hiding AI usage. If a recruiter asks "did you build this yourself?" and you can't explain the Solidity code, you've already lost the offer. Use AI as a teacher, not a ghostwriter.
✕
Skipping the README and demo video. Hiring managers spend 90 seconds on a portfolio project. If your README doesn't hook them in 15 seconds, they close the tab. A Loom video saves your project from being ignored.
